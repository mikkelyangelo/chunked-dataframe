# chunked-dataframe

Режет отсортированный `pandas.DataFrame` на куски по значениям колонки так,
чтобы строки с одинаковым ключом не разъезжались по разным кускам.

## Зачем

Бывает, что фрейм надо обработать частями, но резать его строго по счётчику
строк нельзя: если одна и та же дата попадёт в два куска, дальше поедут все
агрегаты. Здесь размер куска это нижняя граница, а не точное число. Кусок
растёт до ближайшей границы группы и только потом закрывается.

## Как пользоваться

```python
import pandas as pd
from chunker import iter_chunks

ts = pd.date_range("2023-01-01 00:00:01", periods=3, freq="s")
df = pd.DataFrame({"dt": ts.repeat([2, 3, 1])})

for chunk in iter_chunks(df, by="dt", size=3):
    print(len(chunk))
# 5
# 1
```

Шесть строк, три секунды. При `size=3` первая секунда даёт только две строки,
поэтому к ней добавляется вторая, получается кусок из пяти. Последняя секунда
уходит в хвост, там всего одна строка, и это нормально: больше брать неоткуда.

## Как устроено

Границы ищутся бинарным поиском, а не проходом по всем строкам. Чтобы понять,
где закончить кусок, берём строку под индексом `start + size - 1`. Это последняя
строка, которая обязана в него попасть. Дальше расширяем интервал до конца её
группы через `searchsorted(..., side="right")` и получаем ближайшую границу, на
которой кусок уже дорос до нужного размера.

Из этого следует три вещи. Время работы `O(g * log n)`, где `g` это число
кусков, а не число строк. Лишней памяти нужно `O(1)`: нет ни списка кусков, ни
массива границ групп. И сами куски это срезы `iloc`, они не копируют данные.

На фрейме в 10 млн строк (153 МБ) получилось 10 000 кусков за 6.7 секунды при
пике дополнительной памяти 9.5 МБ.

## О чём стоит знать

Ключ должен быть отсортирован по возрастанию. Проверка стоит один проход по
колонке, если сортировка гарантирована выше по стеку, её можно выключить
флагом `assume_sorted`.

Пропуски в ключе не принимаются. `NaT` ломает монотонность, на которой держится
бинарный поиск, и вместо ошибки получилась бы тихая неверная нарезка.

Куски делят память с исходным фреймом, так что менять их на месте не стоит.
Если нужна независимая копия, вызовите `.copy()`.
