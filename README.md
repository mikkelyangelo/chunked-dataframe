# chunked-dataframe

Разбиение отсортированного `pandas.DataFrame` на чанки по значениям колонки так,
чтобы одинаковые значения ключа никогда не оказывались в разных чанках.

## Задача

Дан фрейм с колонкой-ключом, в которой значения повторяются. Нужно нарезать его
на куски заданного размера, соблюдая три условия:

* размер каждого чанка не меньше желаемого;
* значения ключа не пересекаются между чанками;
* расход памяти оптимален.

## Решение

```python
import pandas as pd
from chunker import iter_chunks

ts = pd.date_range("2023-01-01 00:00:01", periods=3, freq="s")
df = pd.DataFrame({"dt": ts.repeat([2, 3, 1])})

for chunk in iter_chunks(df, by="dt", size=3):
    print(len(chunk))
# 5
# 1
```

Границы чанка ищутся не сканированием, а бинарным поиском. Чтобы найти конец
чанка, берём строку под индексом `start + size - 1` — это последняя строка,
которая обязана в него попасть, — и расширяем интервал до конца её группы через
`searchsorted(..., side="right")`. Получается наименьшая граница группы, при
которой чанк уже дорос до нужного размера.

Отсюда свойства:

* сложность `O(g · log n)`, где `g` — число чанков, а не число строк;
* дополнительная память `O(1)`: нет ни списка чанков, ни массива границ;
* чанки возвращаются как срезы `iloc`, которые не копируют данные.

Замер на фрейме в 10 млн строк (153 МБ): 10 000 чанков за 6.7 с, пик
дополнительной памяти 9.5 МБ.

## Ограничения

* Ключ должен быть отсортирован по возрастанию. Проверка стоит один проход по
  колонке и отключается флагом `assume_sorted`.
* Пропуски в ключе отвергаются: `NaT` ломает монотонность, на которой держится
  бинарный поиск, и молча выдал бы неверную нарезку.
* Чанки разделяют память с исходным фреймом, поэтому менять их на месте не
  следует. Нужна независимая копия — вызывайте `.copy()`.
